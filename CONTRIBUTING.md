# Contributing — loop-closer

## Current status: read this first

This is an **internal-first personal project**. It is public so the work can
be inspected, not because it is a community project looking for contributors.
It is being built for one person's use, and whether it is ever offered to
anyone else is a decision the owner has not made.

That means:

- **Issues are welcome** for bug reports and design proposals, using the
  templates provided. A good issue is a contribution.
- **Pull requests are accepted only for changes agreed in an issue first.**
  Open an issue, get the maintainer's agreement there, then send the PR.
  Unsolicited pull requests may be closed without review — this is not a
  judgement on their quality; review capacity is one person plus his agents,
  and the roadmap is his.
- Opening an issue or a PR creates **no entitlement to a response or review
  timeline**. The maintainer may close any issue or PR at any time, without
  debate. Please don't take a closure personally.

## License — there isn't one yet

**No license has been granted for anything in this repository.** All rights
are reserved by the owner. Public visibility is for transparency only; it
does not grant any right to reuse, redistribute, or build on this work beyond
what GitHub's Terms of Service allow for viewing public repositories. If a
license is ever adopted it will be added as a `LICENSE` file by the owner,
and only then.

If you contribute a change that is accepted, you keep your copyright, but you
must be able to certify the Developer Certificate of Origin (below) — i.e.
the change is yours to offer, and you offer it knowing the repository
currently carries no outbound license.

## Developer Certificate of Origin (sign-off required)

Every commit in an accepted pull request must carry a `Signed-off-by:` line
with a real name and email, per the Developer Certificate of Origin, version
1.1 (https://developercertificate.org/). Add it with `git commit -s`. By
signing off you certify that you wrote the contribution or otherwise have
the right to submit it. Commits without sign-off will not be merged.

## Ground rules

- Be civil. Disagreement about the work is fine; hostility is not, and the
  maintainer's moderation decisions are final.
- **Security vulnerabilities are never filed as public issues.** Follow
  [SECURITY.md](SECURITY.md) — private reporting only.
- Do not post secrets, credentials, personal data, or anyone's private
  information in issues, PRs, or comments. They will be removed, and anything
  that looks like a real credential will be treated as compromised.
- If you use AI tools to prepare a contribution, you are still its author:
  you are responsible for every line, and for having read and understood it.

## How review works

All external contributions are reviewed under a defensive process —
diff-first, with CI gated behind maintainer approval, strict dependency
rules, and owner-only merging. The full policy is
[docs/EXTERNAL-REVIEW.md](docs/EXTERNAL-REVIEW.md). Reading it before you
open a PR will save everyone time.
